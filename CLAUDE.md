# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project

**MAZJ (مزج)** is a bilingual (English + Arabic) marketing landing page built with **Next.js 16** (App Router, Turbopack), **React 19**, **Tailwind CSS 3**, and **GSAP**. It is a pixel-faithful animated single-page site served under locale-prefixed routes: `/en` (LTR) and `/ar` (RTL). English is the default; `/` redirects to `/en`.

**Brand facts (not in code):** MAZJ is a single coworking location in **Al Khobar** (Al Olaya district, Al Hayat Tower = برج الحياة "Life Tower"). "الملقى / Al-Malqa" and "المعارج / Al-Ma'arij" are **room names** (the meeting room and the events hall), NOT city districts. Don't "correct" them against the Al-Khobar eyebrow. The 6 bookable facilities live on mazj.sa (URLs in `FACILITIES`, `components/Hero.tsx`). The Google rating is **4.7** with few reviews (NOT 5.0 — a hardcoded `5.0` in the hero trustLine + Proof was a real shipped bug); don't put a rating claim in the hero or Proof, lead with legitimacy signals (address, staffed hours, 24/7 fingerprint, VAT).

## 🔴 i18n content-sync rule (MOST IMPORTANT — read before touching any copy)

All user-facing text lives in `messages/en.json` and `messages/ar.json`, keyed by namespace (`Meta`, `Nav`, `Hero`, `SpaceFinder`, `Usp`, `Steps`, `Why`, `Network`, `StepInto`, `Footer`). Components read strings via next-intl's `useTranslations("Namespace")` — **never hardcode display text in a component.**

**Whenever you change copy in ONE language, you MUST mirror it in the OTHER language in the same edit:**
- Add a key → add it to **both** `en.json` and `ar.json`.
- Reword a string → update the other language's translation to match the new meaning.
- Remove a key → remove it from **both**.

The two files must always share an identical key structure (same namespaces, same keys, arrays the same length). `en.json` is the source of truth for meaning; the Arabic is **Modern Standard Arabic (فصحى)** in a modern marketing register. Keep the brand as `MAZJ` / `مزج`, keep numerals and symbols intact (`$0`, `20%`, `kWh`, `68°F`, `24/7`), and put `\n` line breaks at natural Arabic break points. Never leave one language stale, and never dump raw/literal English into the Arabic file.

## Architecture

**Locale routing (next-intl):**
- `i18n/routing.ts` — locales `["en","ar"]`, `defaultLocale: "en"`, `localePrefix: "always"`.
- `i18n/request.ts` — loads `messages/${locale}.json` per request.
- `i18n/navigation.ts` — locale-aware `Link`/`useRouter`/`usePathname`; use these instead of `next/link` and `next/navigation` so the active locale prefix is preserved.
- `proxy.ts` — Next.js 16 renamed `middleware.ts` to `proxy.ts`; this runs the next-intl middleware for locale detection/prefixing.
- `next.config.mjs` wires `createNextIntlPlugin("./i18n/request.ts")`.
- `app/[locale]/layout.tsx` is intentionally the **only** root layout (there is no `app/layout.tsx`): it sets `<html lang dir>`, calls `setRequestLocale(locale)`, and wraps the tree in `NextIntlClientProvider`. `generateMetadata` reads the `Meta` namespace.

**RTL + fonts:**
- `<html dir="rtl">` is set for Arabic. Prefer **logical** Tailwind utilities (`ps-`/`pe-`, `start-`/`end-`, `text-start`/`text-end`) over physical (`pl-`/`left-`) so layouts mirror correctly.
- Physical *inline* values logical utilities can't reach (clip-path insets, the absolutely-positioned hero chips, the nav pill's asymmetric padding) are flipped in-component via `useLocale() === "ar"` — mirror any new ones.
- Tailwind **directional** utilities are physical and do NOT mirror (`bg-gradient-to-r`, `rotate-*`, etc.). Branch on locale — `rtl ? "bg-gradient-to-l" : "bg-gradient-to-r"` — with **both** class names written literally so the JIT emits them.
- Arabic glyphs are taller than the tight Latin display leading, which clips their tops inside the hero's `.intro-mask` (overflow: clip). `html[lang="ar"]` sets h1/h2/h3/`.font-serif` `line-height: 1.35` to fix it — keep that when adding Arabic headings. Now that headings are all Sans (no `.font-serif`), that rule effectively hooks on **h1/h2/h3**, so make big display headings real heading tags or Arabic clips — e.g. the Why statements render via `Reveal as="h2"` for exactly this reason.
- Fonts are the self-hosted **Thmanyah** family (خط ثمانية, Sans only) in `public/fonts` (`thmanyah-sans-{400,500,700,900}.woff2`); each file carries **both** Latin + Arabic, so there is no per-locale font swap. `app/globals.css` `:root` sets `--font-sans` / `--font-mono` (both = Thmanyah Sans; → Tailwind `font-sans` / `font-mono`). **The whole page is Sans.** Every heading (hero, USP, Steps intro, the Why statements, Network, StepInto, Footer) is `font-sans`; the large section statements are `font-sans font-bold` (700) — Steps intro (`Steps.tsx`), the Why statements (`WhyMazj.tsx`), `Network.tsx`, `StepInto.tsx`. Don't "restore" these to `font-medium`: 500 was the old serif-era weight, deliberately raised to 700. 700 is a real self-hosted weight, so Arabic gets true bold (never synthetic). The **Serif Display** family was fully removed: the woff2 files are deleted, and the `@font-face` blocks + `--font-serif` var are gone (Tailwind's `font-serif` now just falls back to `Georgia`, and nothing uses it). The `html[lang="ar"]` block only neutralizes Latin letter-spacing + bumps heading line-height (no family remap; Tajawal/Aeonik/Feature/Social retired, and those woff2s are also unused). Hero headline (`components/Hero.tsx`) is `font-sans font-black` (Sans 900), subtitle `font-normal`.

**Design system:** tokens (palette, type scale, easings) live in `tailwind.config.ts`. Global CSS (font-face, scroll-reveal, the signature CTA sweep, film-grain overlay, dune/grid textures) lives in `app/globals.css`.

**Design reference (godaylight.com):** the visual system is reskinned from **Daylight Energy**; its canonical tokens are published at `godaylight.com/brand`. Match Daylight's system (crisp radii `2/4/6/16`, mono-UPPERCASE eyebrows tracked `+0.05em` at 12/16px, two-tone headlines with the last phrase in the accent, **straight-slide** CTA sweep — NOT rotated, word-by-word statement reveals via `WordReveal`, `.sf-spectrum` hero wash) EXCEPT keep three MAZJ-owned: **coral `#FF5A48`** (never Daylight's orange `#F66F00`), the **مزج wordmark**, and **Thmanyah**. Wherever Daylight uses orange, MAZJ substitutes coral.

**Motion:** `components/ScrollFX.tsx` (client) registers GSAP ScrollTrigger and drives pinned/clip/scale reveals via `data-fx` / `data-pin-*` attributes on section elements. `components/Reveal.tsx` (client) is a lightweight IntersectionObserver reveal used as the no-JS-safe base layer. Keep these hook attributes intact when editing sections. `components/WordReveal.tsx` (client) is a word-by-word reveal used for the big display headings (Steps, StepInto, the WhyMazj statements, Network); it renders `as="h2"` so Arabic headings stay real heading tags (see the clipping note).

**Hero space-finder (`components/Hero.tsx`, client):** a square media window + facility dropdown. `FACILITIES[]` (config, not copy) maps the 6 real mazj.sa spaces → booking URL + photo (`public/images/spaces/*.jpg`, pulled from mazj.sa's rekaz.io CDN, optimized with `sips`); picking one crossfades its photo into the window and aims the CTA at that page. Copy = `SpaceFinder` namespace. The window is a CSS square: `.sf-stage` (aspect-ratio box, anchored `inset-inline-end`) → `.sf-frame` (clipped: video + `.sf-slide` photo buffers + `.sf-caption`); feature chips `.sf-chip*` anchor to its edges — all via **logical** props so RTL mirrors automatically (styles in `globals.css`).

**CTAs & external links:** the signature button is `components/CtaButton.tsx` (variants `dark`/`light`/`onLavender`/`onTan`; it auto-opens `http(s)` hrefs in a new tab and routes internal paths through the locale-aware `Link`). Outbound destinations are centralized: `lib/links.ts` (`BOOKING` per-space mazj.sa URLs, `SOCIALS`, `ZATCA_TAX_NUMBER`) and `lib/contact.ts` (`WHATSAPP_NUMBER` + `waLink(msg)` localized click-to-chat + `MAPS_URL`, the real Life Tower pin). The sitewide primary CTA is **"Book a tour on WhatsApp"** via `waLink`; booking/checkout still goes to `BOOKING.*` on mazj.sa. Reuse these, never hardcode a number/URL in a component.

**Brand assets:** the MAZJ wordmark is `public/logos/mazj-wordmark.png` (recolored to project ink `#111`; footer and subscribe card re-tint it white with `filter:brightness(0) invert(1)`). Favicon is `app/icon.png`. Outbound links are placeholders (`#`). There is **no icon-only MAZJ symbol**: the wordmark PNG is the only mark. Its transparent alpha also lets it drive a CSS `mask-image` over a solid `backgroundColor` to render the mark in an exact colour (the `StepInto` / `Network` idiom).

## Gotchas & verification

- **`scrollHeight` cannot see TOP overflow — only bottom.** `scrollHeight === clientHeight` does NOT prove text isn't clipped; it silently misses cut-off ascenders (this check once "verified" a live clipping bug as absent). Measure ink with canvas `TextMetrics` using the heading's exact font shorthand (`900 85px "Thmanyah Sans"`) → `actualBoundingBoxAscent`/`Descent`, and find the real baseline by injecting a 0×0 `vertical-align:baseline` probe span into the line.
- **Clipping is a LATIN risk, not just Arabic**, and the cause is the BASELINE, not ink height. `html[lang="ar"] h1,h2,h3{line-height:1.35!important}` rescues Arabic, so tight `lg:leading-[0.98]` only bites **English**. Measured on the hero h1 (Sans 900, 85px): total ink is 78.8px, which *fits* the 83.3px line box — so "ink > line box" wrongly reports OK. What actually clips is that the **baseline sits 73px down**, leaving 10.3px for a 19.5px descender ⇒ ~9.2px of the "g" is guillotined by `.intro-mask{overflow:clip}`, bottom only (top overflow is 0). **Right test:** `descent > (lineBox − baselineOffset)`. Fixed by enlarging the clip box (padding-bottom + negative margin), not by loosening leading — see the comment at `globals.css` `.intro-mask`. Check EN, not just AR, after any weight/leading change.
- **Screenshots:** GSAP makes static headless screenshots catch mid-animation frames. Capture with Playwright `reducedMotion: 'reduce'` (disables ScrollFX + CSS animations) for deterministic final positions. It does **not** pause `<video autoplay loop>`, so the dune/bg videos still paint, which is what you want when verifying a video recolor. The page never reaches Playwright `networkidle` (looping autoplay videos keep the network busy), so wait on `domcontentloaded` + `wait_for_selector('header')` + a short settle instead. If the Chrome extension is unconnected, delegate capture to a subagent (system `chrome --headless=new --screenshot`, or Playwright).
- **Adding/verifying a font:** `fonttools` (Python) is installed — check a woff2's glyph coverage (Arabic `U+0627` + Latin present) before wiring it. External font CDNs (e.g. `framerusercontent.com`) aren't in the sandbox network allowlist → curl font binaries with the sandbox disabled (`github.com` / `raw.githubusercontent.com` ARE allowed). Standalone HTML font specimens need `<meta charset="utf-8">` or Arabic mojibakes, and Playwright MCP can't open `file://` (serve over 127.0.0.1 with a UTF-8 charset).
- **The visible "brand orange" is mostly video, not CSS** (`footer-dune.mp4`, `step-card.mp4`, and the hero clip-window's `hero.mp4`; `mazj-button.mp4` is **orphaned**, since the header CTA reuses `hero.mp4` instead, which the hero box has already cached). Changing the `orange` token / CSS won't recolor those — the videos must be hue-shifted or replaced.
- **Video `poster`s must be the video's own first frame.** The hero bg (`mazj-hero.mp4` → `hero-bg.jpg`) and the desktop clip-window (`hero.mp4` → `hero-video.jpg`) each poster a still shown until the heavy video (bg is ~13 MB) decodes, so a mismatched poster (several were stale solar-template leftovers) flashes a wrong image on hard refresh. When swapping any section video, regenerate its poster from frame 0 at the video's native res (1280×720, not higher, or the sharper poster pops when the video takes over): `ffmpeg -y -i public/videos/X.mp4 -frames:v 1 -q:v 2 public/images/X.jpg`. `ffmpeg`/`ffprobe` are installed.
- **Black bars in a card are probably baked into the asset, not an `object-fit` bug.** `step-reserve.jpg` shipped 133px of pure black top+bottom *inside the JPEG* (a squarish photo padded onto a 3:4 canvas), so `object-cover` was correct all along and the CSS was innocent. Check the file's edge rows before touching CSS. When trimming such bars, the codec smears the hard black→photo edge, so the first surviving row is half-black and renders as a dark hairline: trim **+1px** past the detection threshold, and re-cut from the **original** file rather than one you already re-saved (double JPEG compression).
- **Recolor a baked-orange video to an exact hex:** overlay a solid `bg-[#hex]` div with `mix-blend-mode:color` over the `<video>`, wrapped in `isolate` (scopes the blend to the video). Not `filter:hue-rotate()`: browsers under-rotate saturated orange, so it misses the exact hue. blend:color keeps the source's luminosity, so dim brighter videos first with `[filter:brightness(0.x)]`. Live in `Hero.tsx`, `Footer.tsx`, `Steps.tsx` (SubscribeCard), `Navigation.tsx` (CTA hover). `orange` token = `#FF5A48`.
  - **Derive the dim, never guess it.** blend:color takes lightness from the video, so the dim *is* the final lightness. Measure mean luma: `ffmpeg -v error -i v.mp4 -vf "fps=1,signalstats,metadata=print:key=lavfi.signalstats.YAVG:file=-" -f null -`. `hero`/`step-card`/`mazj-button` are the same dune re-cropped (Y≈138), so all three take the identical `brightness(0.78)`; `footer-dune` is Y≈83 and takes none. Matching luma is what makes two elements read as the same coral.
  - **Stack the overlay BELOW white content in DOM order.** blend:color repaints everything beneath it: the subscribe card's white wordmark and the CTA's white label stay white only because they paint *after* the overlay. Put it above them and they turn coral.
  - **Verify by HUE, not RGB.** Recolored reads ≈6°, raw baked orange ≈25-30°. RGB means legitimately drift ~15/255 between elements (different `object-cover` crops of the same gradient), so a channel delta proves nothing; hue is the discriminator.
- **Hero space-finder dropdown is portaled to `document.body`** (`components/Hero.tsx`, JS-positioned below the pill): the hero `<section>` is `overflow-clip` and the next section (`USP`) is `relative z-10` on cream, so an in-tree `.sf-panel` gets clipped or painted behind the cream. Preserve the portal, the `panelRef` outside-click check, and the scroll/resize reposition when editing it.
- **i18n keys:** when regenerating copy (esp. via agents/workflows), keys get silently renamed or dropped. Validate the new `messages/*.json` keys against the components' `t("...")` keys (and each other) before writing. Concretely: diff the two files' leaf-key PATHS (incl. array indices) with a quick node script, not by eye — it catches renamed/dropped keys and array-length drift.
- **Verify metadata/i18n without a browser:** `curl -s localhost:3000/en` + `/ar`, grep the `<head>` (`<title>`, `og:*`, `hreflang`, canonical) to confirm each locale renders fully in its own language. curl needs the sandbox off (see `.claude.local.md`).
- **Playwright MCP** writes screenshots only **inside the repo root** (sandbox) — save there, then move to the scratchpad. Flaky under contention ("Browser is already in use" from a stale lock); retry, or clear stale `Singleton*` in its `ms-playwright-mcp` cache (sandbox off).
- After rapid edits the editor's inline TS diagnostics lag and show **phantom** errors (names from just-removed code); `node_modules/.bin/tsc --noEmit` is the source of truth.
- **Format-on-save linter** rewrites Tailwind arbitrary values (`tracking-[-0.24px]`→`tracking-[0.05em]`, `text-11`→`text-12`) and can swap a heading to `WordReveal`, so a component may change on disk mid-task: re-Read it before a dependent edit.
- `next.config.mjs` / `proxy.ts` changes need a dev-server restart; Tailwind/CSS/component edits hot-reload.
- **`mazj-hero.mp4` is trimmed at 55.85s** (66.42s → 55.87s) to cut the promo's branded outro: a red MAZJ wordmark + `مساحة عمل مشتركة` overlay hard-cuts in at **55.86s**, followed by contact details (`احجز الآن` / `www.mazj.org` / `013 3300 337`) and trailing black. It loops as the hero bg, so the outro was surfacing on every cycle. If you ever re-pull the YouTube promo, re-trim it: `ffmpeg -i src.mp4 -t 55.85 -c copy mazj-hero.mp4` (stream copy = lossless, and frame 0 is preserved so `hero-bg.jpg` stays a valid poster). Keep the MAZJ logo at ~52s — that's real signage on the glass, not the outro.
- **Real MAZJ media sources** (for replacing leftover/template imagery): *photos* come from mazj.sa's rekaz store: fetch its space pages (`/reservation/*`, `/subscription/*`, sandbox OFF), grep `cdn.rekaz.io/tenants/3a14a1b1-1f18-24e9-bfb1-a77ce84ff72a/<id>`, then get a real JPEG at any size via `img.rekaz.io/cdn-cgi/image/quality=90,width=N,f=jpeg/<raw-cdn-url>` (raw CDN URLs are extensionless / not always JPEG). *Video B-roll:* the official YouTube promo `wAAxwPWoRtI` ("Mazj Space - Al Khobar", clean, no captions/talking-heads). Instagram @mazjorg needs a real IG login in Chrome (`yt-dlp --cookies-from-browser chrome https://www.instagram.com/reel/<shortcode>/`).
- **Seamless background-video loops:** cut ONE clean B-roll shot (no mid-cut, no burned-in captions), then boomerang it (`[0]split[a][b];[b]reverse[r];[a][r]concat`) so the loop never jumps; `setpts=N*PTS` to slow it. Ken Burns (zoompan + boomerang) off a still is the fallback when there's no clean footage.
- **Review many images/frames in one Read** by tiling: `ffmpeg -pattern_type glob -i '*.jpg' -filter_complex "scale=W:H,tile=CxR" -frames:v 1 sheet.jpg`. `drawtext` isn't compiled into this ffmpeg build, so print a cell→file/timestamp legend instead of burning labels in.

## Adding a section
Create the component in `components/`, add its namespace to **both** message files, render it in `app/[locale]/page.tsx`. Server components can call `useTranslations` directly; client components work because the whole tree is under `NextIntlClientProvider`.
