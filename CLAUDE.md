# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project

**MAZJ (مزج)** is a bilingual (English + Arabic) marketing landing page built with **Next.js 16** (App Router, Turbopack), **React 19**, **Tailwind CSS 3**, and **GSAP**. It is a pixel-faithful animated multi-page site (home + `/about` `/contact` `/events` `/faq` `/privacy` `/spaces` `/terms` under `app/[locale]/`; `/pricing`→`/spaces` and `/community`→`/about` are redirects in `next.config.mjs`) served under locale-prefixed routes: `/en` (LTR) and `/ar` (RTL). English is the default; `/` redirects to `/en`.

**Brand facts (not in code):** MAZJ is a single coworking location in **Al Khobar** (Al Olaya district, Al Hayat Tower = برج الحياة "Life Tower"). "الملقى / Al-Malqa" and "المعارج / Al-Ma'arij" are **room names** (the meeting room and the events hall), NOT city districts. Don't "correct" them against the Al-Khobar eyebrow. mazj.sa sells **4** products (was 6): duration is now a variant picker inside each, not a product. `BOOKING` = `sharedSeat`/`privateOffice`/`meeting`/`event`. Re-verify these URLs before trusting them; `mktb-khas-hyz` already 404s. The Google rating is **4.7** with few reviews (NOT 5.0 — a hardcoded `5.0` in the hero trustLine + Proof was a real shipped bug); don't put a rating claim in the hero or Proof, lead with legitimacy signals (address, staffed hours, 24/7 fingerprint, VAT).

## 🔴 i18n content-sync rule (MOST IMPORTANT — read before touching any copy)

All user-facing text lives in `messages/en.json` and `messages/ar.json`, keyed by namespace (`Meta`, `Nav`, `Hero`, `SpaceFinder`, `Usp`, `Steps`, `Why`, `Network`, `StepInto`, `Footer`, plus section namespaces like `Faq`/`Proof`/`Founding`/`HostEvent`/`Location`/`Spaces`, one `*Page` namespace per route, and a `Space*` namespace per space-detail page). Components read strings via next-intl's `useTranslations("Namespace")` — **never hardcode display text in a component.**

**Whenever you change copy in ONE language, you MUST mirror it in the OTHER language in the same edit:**
- Add a key → add it to **both** `en.json` and `ar.json`.
- Reword a string → update the other language's translation to match the new meaning.
- Remove a key → remove it from **both**.

The two files must always share an identical key structure (same namespaces, same keys, arrays the same length). `en.json` is the source of truth for meaning; the Arabic is **Modern Standard Arabic (فصحى)** in a modern marketing register. Keep the brand as `MAZJ` / `مزج`, keep numerals and symbols intact (`$0`, `20%`, `kWh`, `68°F`, `24/7`), and put `\n` line breaks at natural Arabic break points. Never leave one language stale, and never dump raw/literal English into the Arabic file.

**Arabic city spelling is settled: `الخُبر`** (damma only), in all 27 occurrences including every `metaTitle`. Do NOT "correct" it to bare `الخبر` or fully-vocalized `الخُبَر`: a native reviewer WILL flag the partial vocalization as a half-measure (and note that bare `الخبر` also reads as "the news"), and it was kept anyway for consistency with the body copy. Change it only on an explicit, site-wide instruction.

**AR product vocabulary is settled — reuse it, never coin a synonym.** Day pass = **الدخول اليومي** (NOT "تذكرة يومية" — a session coined that and a native review failed it), open desk = المكتب المرن, private office = حيّز / المكتب الخاص, meeting room = الملقى, events hall = المعارج. Before writing new AR copy, `str.count` the existing ar.json for the term you're about to use.

**Bulk-editing `messages/*.json`:** both files round-trip byte-identical via python `json.dump(d, f, indent=2, ensure_ascii=False)` + trailing `\n`, so insert many keys programmatically (assert each replacement hits exactly once), then re-verify leaf-key path parity.

## Architecture

**Locale routing (next-intl):**
- `i18n/routing.ts` — locales `["en","ar"]`, `defaultLocale: "en"`, `localePrefix: "always"`.
- `i18n/request.ts` — loads `messages/${locale}.json` per request.
- `i18n/navigation.ts` — locale-aware `Link`/`useRouter`/`usePathname`; use these instead of `next/link` and `next/navigation` so the active locale prefix is preserved.
- `proxy.ts` — Next.js 16 renamed `middleware.ts` to `proxy.ts`; this runs the next-intl middleware for locale detection/prefixing.
- `next.config.mjs` wires `createNextIntlPlugin("./i18n/request.ts")`.
- `app/[locale]/layout.tsx` is intentionally the **only** root layout (there is no `app/layout.tsx`): it sets `<html lang dir>`, calls `setRequestLocale(locale)`, and wraps the tree in `NextIntlClientProvider`. `generateMetadata` reads the `Meta` namespace.

**RTL + fonts:**
- `<html dir="rtl">` is set for Arabic. Prefer **logical** Tailwind utilities (`ps-`/`pe-`, `start-`/`end-`, `text-start`/`text-end`) over physical (`pl-`/`left-`) so layouts mirror correctly.
- Physical *inline* values logical utilities can't reach (clip-path insets, the absolutely-positioned hero chips, the nav pill's asymmetric padding) are flipped in-component via `useLocale() === "ar"` — mirror any new ones.
- Tailwind **directional** utilities are physical and do NOT mirror (`bg-gradient-to-r`, `rotate-*`, etc.). Branch on locale — `rtl ? "bg-gradient-to-l" : "bg-gradient-to-r"` — with **both** class names written literally so the JIT emits them.
- Arabic glyphs are taller than the tight Latin display leading, which clips their tops inside the hero's `.intro-mask` (overflow: clip). `html[lang="ar"]` sets h1/h2/h3/`.font-serif` `line-height: 1.35` to fix it — keep that when adding Arabic headings. Now that headings are all Sans (no `.font-serif`), that rule effectively hooks on **h1/h2/h3**, so make big display headings real heading tags or Arabic clips — e.g. the Why statements render via `Reveal as="h2"` for exactly this reason.
- Fonts are the self-hosted **Thmanyah** family (خط ثمانية, Sans only) in `public/fonts` (`thmanyah-sans-{400,500,700,900}.woff2`); each file carries **both** Latin + Arabic, so there is no per-locale font swap. `app/globals.css` `:root` sets `--font-sans` / `--font-mono` (both = Thmanyah Sans). **All 45 `font-mono` classes were deleted** — it was a no-op alias for the sans face. The label register is now `.eyebrow` in globals.css (weight 500 + uppercase + `var(--eyebrow-tracking)`); colour and size stay as Tailwind utilities at the call site so they never fight it on specificity. It is keyed on WEIGHT because `uppercase` and `letter-spacing` are **both** no-ops in Arabic, so weight is the only signal that survives either writing system. **The whole page is Sans.** Every heading (hero, USP, Steps intro, the Why statements, Network, StepInto, Footer) is `font-sans`; the large section statements are `font-sans font-bold` (700) — Steps intro (`Steps.tsx`), the Why statements (`WhyMazj.tsx`), `Network.tsx`, `StepInto.tsx`. Don't "restore" these to `font-medium`: 500 was the old serif-era weight, deliberately raised to 700. 700 is a real self-hosted weight, so Arabic gets true bold (never synthetic). The **Serif Display** family was fully removed: the woff2 files are deleted, and the `@font-face` blocks + `--font-serif` var are gone (Tailwind's `font-serif` now just falls back to `Georgia`, and nothing uses it). The `html[lang="ar"]` block only neutralizes Latin letter-spacing + bumps heading line-height (no family remap; Tajawal/Aeonik/Feature/Social retired, and those woff2s are also unused). Hero headline (`components/Hero.tsx`) is `font-sans font-black` (Sans 900), subtitle `font-normal`.

**Design system:** tokens (palette, type scale, easings) live in `tailwind.config.ts`. Global CSS (font-face, scroll-reveal, the signature CTA sweep, film-grain overlay, dune/grid textures) lives in `app/globals.css`.

🔴 **User-approved exception — the hero `.qualify-pill` is NO LONGER Daylight's glass**, it is rebuilt on Apple's Liquid Glass. Daylight has **no** liquid glass: verified zero `feDisplacementMap` / `feTurbulence` / `backdrop-filter:url()` / inset shadows across all 102k chars of their CSS. Theirs is just `blur(6px) saturate(110%)` + 5% white fill + a 1px `rgba(255,255,255,.22)` rim (PURE WHITE, not beige — beige only on `:focus-within`) + 12px radius, inner button 8px. ## Gotchas & verification

- **Overflow checks need BOTH methods.** `body` and `<main>` both set `overflow-x:hidden`, so `documentElement.scrollWidth` under-reports and reads clean while content overflows — walk each element's bounding rect against the viewport box (check both edges; RTL overflows left). But that rect walk MISSES text overflowing its own box (`whitespace-nowrap`), since the box stays at container width — only `el.scrollWidth > el.clientWidth` on that element catches it. Run both.
- **`text-wrap` is applied site-wide:** `text-balance` on section headings, `text-pretty` on body copy. Section titles carry hand-placed line breaks and render via `whitespace-pre-line`; `balance`/`pretty` coexist with it (the hard breaks win, so `balance` only evens the soft wraps). Exception: the hero H1 (manual `.intro-line` split) must never get `text-balance`. `PageIntro` is the shared sub-page opener (~9 routes): `WordReveal` h1 + ruled meta row + optional route media, or the `dot-field` texture when `image` is omitted (reference routes — faq/privacy/terms — deliberately stay quiet). Keep its `<h1>` a real `<h1>` for the Arabic clip rule.
- **`scrollHeight` cannot see TOP overflow — only bottom.** `scrollHeight === clientHeight` does NOT prove text isn't clipped; it silently misses cut-off ascenders (this check once "verified" a live clipping bug as absent). Measure ink with canvas `TextMetrics` using the heading's exact font shorthand (`900 85px "Thmanyah Sans"`) → `actualBoundingBoxAscent`/`Descent`, and find the real baseline by injecting a 0×0 `vertical-align:baseline` probe span into the line.
- **Clipping affects BOTH scripts, and the cause is the BASELINE, not ink height.** The right test is `descent > (lineBox − baselineOffset)`; "ink > line box" wrongly reports OK (hero h1 at Sans 900/85px: ink 78.8px *fits* the 83.3px box, yet the baseline sits 73px down, leaving 10.3px for a 19.5px descender). Clipping is bottom-only; top overflow is 0. Fix by enlarging the clip box (padding-bottom + matching negative margin), never by loosening leading. See the comment at `globals.css` `.intro-mask`.
  - 🔴 **ARABIC is the WORSE case, not the rescued one.** This bullet previously claimed `html[lang="ar"]{line-height:1.35}` rescues Arabic so only English clips. That was wrong and shipped for a while. Arabic descenders are ~2× Latin's at the same size, so 1.35 is *not enough*: measured AR `اعمل في` clipped **+4.35px at 85px** and **+2.16px at 40px**, while EN `good company.` was **clean** (0.51px spare at 85px, 1.19px at 40px). Confirmed two independent ways that agreed: canvas `TextMetrics` with a 0×0 `vertical-align:baseline` probe span, and a pixel-diff A/B toggling `overflow:clip`→`visible` (ar-1440 restored 4.33px across 367 changed pixels; en-1440 and en-390 both returned bbox `None`, **zero** pixels changed). Visually it is the two dots under the final ي of `في` flattened into trapezoids. **Check AR first, then EN** — EN's 0.51px margin is one weight/leading change from breaking too.
  - The mask padding has a hard ceiling: `.intro-line` animates in from `translateY(120%)`, so padding must stay ≤ **0.2em** of the line-height or the incoming line shows before it animates. Arabic needs ~0.051em, so it fits, but verify at **both** the 85px desktop and 40px mobile sizes (the ceiling is relative to line-height, and the two differ).
  - **The `h1,h2,h3` rescue cannot reach a `<span>`.** Arabic display text in a non-heading tag needs explicit `leading-[1.35]`. Measured live in `WhyMazj.tsx` (`Reveal as="span"`, `lg:text-45 leading-tight`): at 1024 AR the ink is **71.24px inside a 56.25px line box**, a −14.99px gap, i.e. adjacent lines' glyph ink physically collides. EN clears by +5 to +11px at every size.
- **Screenshots:** GSAP makes static headless screenshots catch mid-animation frames. Capture with Playwright `reducedMotion: 'reduce'` (disables ScrollFX + CSS animations) for deterministic final positions. It does **not** pause raw `<video autoplay loop>` — but on footered routes MotionToggle now auto-pauses them under reduced motion (frozen on one frame). A frozen frame still paints (fine for a recolor check), but you can't sample frame-to-frame over-video contrast in that context: measure with motion ON, ≥12 frames. The page never reaches Playwright `networkidle` (looping autoplay videos keep the network busy), so wait on `domcontentloaded` + `wait_for_selector('header')` + a short settle instead. If the Chrome extension is unconnected, delegate capture to a subagent (system `chrome --headless=new --screenshot`, or Playwright).
- **Browser capture routes:** Python Playwright works (`python3 -m playwright`, Chromium installed); node/`npx playwright` does NOT (root-owned npm cache blocks it). System `chrome --headless=new --screenshot` sometimes never exits after writing the file — poll for the file then kill, and give it a scratch `--user-data-dir`. `--force-prefers-reduced-motion` gets deterministic static captures without Playwright.
- **Adding/verifying a font:** `fonttools` (Python) is installed — check a woff2's glyph coverage (Arabic `U+0627` + Latin present) before wiring it. ## Adding a section
Create the component in `components/`, add its namespace to **both** message files, render it in `app/[locale]/page.tsx`. Server components can call `useTranslations` directly; client components work because the whole tree is under `NextIntlClientProvider`.
